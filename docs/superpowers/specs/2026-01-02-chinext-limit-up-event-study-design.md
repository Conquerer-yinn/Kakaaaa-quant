# 创业板涨停后 5 日事件研究设计

## 目标

在现有 `Kaka_Quant` 仓库中落地第一条真实策略研究闭环：识别指定区间内的创业板涨停事件，观察事件后第 1、3、5 个交易日的收盘表现，生成可人工复盘的 Excel，并在现有 FastAPI 与 React 页面中展示最新研究结果。

这条闭环的价值不是证明某个策略可以赚钱，而是验证项目能否稳定完成：

`研究问题 -> 历史样本 -> 指标计算 -> Excel 产物 -> API -> 前端复盘`

## 范围

### 本次包含

- 清理远端主线遗留的硬编码 Tushare Token、飞书 Webhook 默认值和归档中的真实 Webhook。
- 自定义 Tushare 网关默认关闭，启用时必须使用有效 HTTPS URL。
- 建立 Python `unittest` 测试基线，不新增测试依赖。
- 识别代码以 `300`、`301` 开头且 Tushare `limit_list_d.limit == "U"` 的创业板涨停事件。
- 计算事件后第 1、3、5 个交易日的收盘收益率。
- 计算 5 日观察窗口内的最高收盘收益率和最低收盘收益率。
- 对完整样本生成均值、中位数、正收益比例、最大值和最小值汇总。
- 输出 `研究摘要`、`事件明细`、`运行信息` 三个 Excel sheet。
- 提供最新结果读取接口与同步运行接口。
- 将 `/strategies` 从占位页改成真实研究结果页。
- 更新策略注册表、README 和项目状态文档。

### 本次不包含

- 交易成本、滑点、仓位或买卖执行模拟。
- 盘中触发条件和分钟级数据。
- 自动定时调度。
- 数据库、任务队列或复杂任务状态机。
- 策略研发 Agent、知识库或多 Agent 编排。
- 将事件研究结果描述成已验证的盈利策略。

## 研究口径

### 样本定义

- 事件日必须位于用户指定的 `start_date` 与 `end_date` 之间。
- 股票代码必须以 `300` 或 `301` 开头。
- `limit_list_d` 中 `limit` 必须为 `U`。
- 事件日必须能在日线行情中找到有效收盘价。
- 事件日之后必须至少存在 5 个完整交易日；不完整样本不进入收益统计，但计入跳过数量。

### 收益定义

对每个完整事件样本，以事件日收盘价为基准：

`N 日收益率 = (事件后第 N 个交易日收盘价 / 事件日收盘价 - 1) * 100`

本次计算：

- `1日收益率(%)`
- `3日收益率(%)`
- `5日收益率(%)`
- `5日内最高收盘收益率(%)`
- `5日内最低收盘收益率(%)`

收益率统一保留两位小数。

### 汇总定义

对 1、3、5 日收益分别统计：

- 样本数
- 平均收益率
- 中位数收益率
- 正收益比例
- 最大收益率
- 最小收益率

## 架构

### 纯计算层

`strategies/chinext_limit_up_event_study.py`

- 只接收交易日、涨跌停表和日线表。
- 不访问网络、不写文件。
- 返回事件明细、汇总和跳过样本元数据。
- 作为主要单元测试对象。

### 工作簿层

`strategies/chinext_limit_up_workbook.py`

- 负责结果文件命名。
- 负责写入三个 sheet。
- 负责定位最新研究文件。
- 不包含研究计算。

### 运行层

`strategies/run_chinext_limit_up_event_study.py`

- 解析日期区间。
- 使用 `TushareDataEngine` 拉取交易日、日线和涨停表。
- 调用纯计算层。
- 调用工作簿层输出 Excel。
- 支持 CLI 和后端同步调用。

### API 层

- `GET /strategies/chinext-limit-up-event-study`
  - 返回最新工作簿中的摘要、运行信息和最近事件明细。
- `POST /strategies/chinext-limit-up-event-study/run`
  - 接收可选 `start_date`、`end_date`。
  - 同步执行研究并返回最新结果。

同步执行符合当前 FastAPI 轻量边界。前端必须明确展示运行中状态；后续如果真实运行耗时不可接受，再复用现有后台任务模式升级。

### 前端层

`/strategies` 页面展示：

- 研究定位和口径说明。
- “运行最近 120 天研究”按钮。
- 完整样本数、候选事件数、跳过样本数、最新事件日。
- 1、3、5 日汇总表。
- 最近事件明细表。
- 空数据、运行中和错误状态。

页面不注入假数据；没有工作簿时展示明确的首次运行提示。

## 数据与错误处理

- Tushare Token 缺失时返回可读错误，不回退到仓库内默认凭据。
- 自定义 Tushare 网关必须显式配置且使用 HTTPS，避免 Token 发送到明文第三方端点。
- 指定日期格式无效或开始日期晚于结束日期时立即拒绝。
- 研究区间没有交易日或没有完整样本时仍生成结构稳定的结果，页面显示零样本说明。
- 单个事件缺失事件日行情时跳过并计数。
- 事件后不足 5 个交易日时跳过并计数。
- Excel 被占用时沿用现有 `ExcelHelper` 的清晰错误信息。

## 测试策略

### 单元测试

- 创业板代码过滤和涨停事件识别。
- 1、3、5 日收益率与窗口极值。
- 不完整未来窗口跳过。
- 缺失事件日行情跳过。
- 汇总指标。
- 工作簿命名、写入和最新文件读取。
- API 结果组装。
- 配置文件不包含硬编码敏感默认值。

### 集成与静态验证

- Python 全量 `unittest`。
- 所有 Python 文件 AST 解析。
- FastAPI OpenAPI 中包含两个新接口。
- React `npm run build`。
- 使用真实 Tushare 数据运行一个短区间研究；若外部凭据或网络不可用，则保留明确验证缺口。

## 验收标准

- `python -m unittest discover` 全部通过。
- 最新研究 Excel 能生成并包含三个约定 sheet。
- GET 接口能读取工作簿并返回结构化结果。
- POST 接口能调用研究任务并返回结果或可读错误。
- `/strategies` 不再是占位页，且构建通过。
- 当前分支不再包含硬编码 Token/Webhook 默认值。
- 当前工作树的受跟踪文本不包含真实 Token/Webhook；历史凭据仍需在服务端轮换。
- README、策略注册表和项目状态与实现一致。

# 综合研究任务与独立标准任务拆分原则

## 结论

`market` 下的任务当前明确分成两类：

1. 独立标准任务
2. 综合研究任务

## 两类任务定义

### 1. 独立标准任务

特征：

- 单入口
- 单主题
- 单输出
- 可单独运行
- 后续更容易被 API、调度或通知单独调用

当前代表：

- `market/jobs/run_daily_basics.py`

### 2. 综合研究任务

特征：

- 一个主入口编排多个指标模块
- 多个指标共同服务于同一研究主题
- 最终汇总到同一个工作簿
- 更贴近真实研究工作流

当前代表：

- `market/jobs/run_market_sentiment.py`

## 当前阶段判断规则

以下情况允许继续保留为综合研究任务：

1. 多个表本来就服务于同一研究主题。
2. 日常观察时本来就希望一起看。
3. 更新频率和使用场景基本一致。
4. 最终集中到同一个 Excel 工作簿更符合真实工作流。

以下情况才考虑升级成独立标准任务：

1. 该模块本身具备单独运行价值。
2. 该模块单独输出就有完整研究价值。
3. 它的数据来源、更新频率或使用场景与原综合任务明显不同。
4. 它未来很可能被 API 或统一调度单独调用。

## 明确不做

1. 不为了目录整齐强行拆散综合研究任务。
2. 不因为引入 API，就把一个 Excel 多个 sheet 的输出方式判定为不合理。
3. 不为了抽象而把所有指标都提前包装成统一任务协议。

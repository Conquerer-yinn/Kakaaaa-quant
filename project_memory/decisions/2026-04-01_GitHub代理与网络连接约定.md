# GitHub 代理与网络连接约定

## 背景

项目在推送到 GitHub 时，曾多次遇到：

1. `Connection was reset`
2. `Could not connect to server`
3. 本地仓库提交已完成，但无法直接 `push origin main`

这说明后续 AI 在做仓库同步时，需要把“网络可达性”和“代理可用性”一起考虑，而不是默认直连一定可用。

## 当前约定

当前环境如果直连 GitHub 失败，优先尝试本地代理：

- `127.0.0.1:7897`

推荐临时命令：

```powershell
git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 push origin main
```

需要拉取时：

```powershell
git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 pull origin main
```

## 为什么这样定

1. 这个方式对当前仓库生效，使用成本低。
2. 不需要先全局改 Git 配置，也更适合在网络不稳定时临时切换。
3. 后续其他窗口如果再次遇到 GitHub 不可达，可以直接按这条约定处理，减少重复沟通。

## 对后续 AI 的提醒

1. 如果 `git push` 失败，先区分是认证问题还是网络问题。
2. 如果是网络问题，优先尝试本地代理，而不是反复裸连重试。
3. 在用户已经明确提供代理地址的前提下，应把该约定同步沉淀到 `project_memory/decisions/`。

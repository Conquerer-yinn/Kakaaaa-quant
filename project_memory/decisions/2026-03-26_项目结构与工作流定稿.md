# 项目结构与工作流定稿

## 背景

项目最初参考了较重的重构结构，但在讨论过程中发现不够贴近真实工作流。

## 决策内容

1. 项目分为两条主线：
   - `market/`：行情分析、指标观察、盘中盘后辅助判断
   - `strategies/`：策略研究、历史筛选、Excel 复盘、成熟后纳入日常运行
2. 行情线统一放在 `market/` 下：
   - `market/jobs/`
   - `market/indicators/`
3. 策略直接放在 `strategies/` 下，不再单独保留 `jobs/strategy/`。
4. 策略是否纳入日常运行，由 `strategies/strategy_registry.yaml` 控制。
5. 指标如果需要复用、反复调整、可能被别的任务调用，再抽到 `market/indicators/`；否则可以先写在任务脚本里。

## 为什么这样定

1. 更贴近用户当前“脚本式研发 + 逐步沉淀”的工作流。
2. 行情线业务上本来就是一类事情，目录上统一更自然。
3. 策略大多是独立研究脚本，不需要额外套一层任务目录。

## 影响范围

后续新增行情任务统一放在 `market/` 下；新增策略统一放在 `strategies/` 下。

# 项目协作与记忆方案

## 背景

当前项目会长期依赖多个聊天窗口和多个子代理共同推进，但聊天记录本身未必适合作为唯一长期知识库，尤其在 team、workspace、账号切换时存在不确定性。

## 决策内容

1. 当前主对话窗口用于处理项目整体设计、架构、部署、版本控制等全局事务。
2. 长期主题可以单独开主对话窗口，例如：
   - 指标体系设计
   - 策略体系与盈利模式复盘
3. 具体实现类工作交给子代理处理，例如：
   - 旧脚本迁移
   - 新指标开发
   - 新策略开发
4. 项目知识不只保留在聊天窗口中，还要同步沉淀到仓库内的 `project_memory/`。
5. 长期保存分两层：
   - 原始对话归档
   - 结构化结论沉淀

## 为什么这样定

1. 主对话适合长期上下文，但不适合承载所有细节执行。
2. 子代理适合并行推进具体任务，但不适合作为唯一长期回看入口。
3. 仓库内 Markdown 文档最容易迁移，也最容易和代码一起长期维护。

## 影响范围

后续与项目整体相关的重要结论，都建议同步沉淀到 `project_memory/`。

## 后续待确认

1. 是否要为“指标体系”与“策略体系”分别建立长期决策文档。
2. 是否要增加自动化方式来辅助保存重要对话摘要。

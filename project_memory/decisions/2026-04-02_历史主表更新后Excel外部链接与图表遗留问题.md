# 历史主表更新后 Excel 外部链接与图表遗留问题

## 日期

2026-04-02

## 背景

`market-sentiment` 已经切换到“历史主表增量补充”的真实工作流：

1. 识别当前历史主表，例如 `历史数据_20260101_20260320.xlsx`
2. 生成 `补充数据_起始日期_结束日期.xlsx`
3. 把补充数据并回历史主表
4. 更新历史主表文件名为新的覆盖区间，例如 `历史数据_20260101_20260402.xlsx`

## 当前现象

更新后的历史主表在 Excel 打开时出现修复提示，原始恢复日志如下：

```xml
<?xml version="1.0" encoding="UTF-8" standalone="yes"?>
<recoveryLog xmlns="http://schemas.openxmlformats.org/spreadsheetml/2006/main"><logFileName>error295880_02.xml</logFileName><summary>在文件“D:\code\Kaka_Quant\storage\data_master\历史数据_20260101_20260402.xlsx”中检测到错误</summary><repairedRecords><repairedRecord>已修复的记录: /xl/externalLinks/externalLink1.xml 部分的 外部公式引用 (来自外部公式引用的缓存值)</repairedRecord></repairedRecords></recoveryLog>
```

同时还有一个业务现象：

1. 历史主表里的图表没有按预期自动更新。
2. 即使数据 sheet 已经补到了最新日期，图表展示仍可能停留在旧范围。

## 初步判断

当前最可疑的方向有两个：

1. 历史主表模板中原本就带有外部链接引用或缓存。
   - 例如图表、命名区域、公式引用过其他工作簿。
   - 程序在复制旧主表并重写数据 sheet 后，保留了这些 `externalLinks` 关系。
   - Excel 打开时发现缓存或引用关系不一致，于是自动修复。
2. 图表数据源并没有完全绑定在程序维护的 Excel Table 上。
   - 如果图表仍然引用固定区域、旧文件名、外部工作簿、命名区域缓存，
     那么即使数据 sheet 更新，图表也不会跟着刷新。

## 当前已确认的边界

1. 程序只重写数据 sheet 和 `总览` 上方摘要区，不主动生成图表。
2. 程序会保留工作簿中的其他 sheet、图表模板和潜在外部链接关系。
3. 这意味着当前方案对“模板里的图表引用是否干净”有依赖。

## 建议后续排查顺序

1. 解压出问题的 `.xlsx`，检查：
   - `xl/externalLinks/`
   - `xl/_rels/workbook.xml.rels`
   - 相关 chart / drawing / workbook 定义
2. 在 Excel 中逐项检查：
   - 数据 -> 编辑链接
   - 名称管理器
   - 图表系列公式
   - 是否还引用旧文件名或外部工作簿
3. 确认图表是否基于 Excel Table 而不是固定区域。
4. 如果外部链接只来自历史模板，可考虑在程序写回后增加“清理无效 externalLinks”的步骤。
5. 如果图表仍依赖固定区域，需把模板改造成真正绑定 Table 或命名区域的形式。

## 当前处理策略

这次先不在代码里继续硬改这一块，原因是：

1. 需要先看真实模板结构，避免误删合法引用。
2. `externalLinks`、命名区域、图表公式之间有耦合，直接程序级删除有风险。
3. 当前更适合先保留现象和恢复日志，后续针对模板做一次定向排查。

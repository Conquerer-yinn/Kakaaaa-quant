# 市场卡片推送与三层结构约定

## 背景

围绕市场指标体系继续推进时，项目已经不再只有 Excel 输出，还开始接入飞书卡片推送。

在实际落第一版盘后卡片时，曾出现一个结构性问题：

- 为了快速打通推送链路，飞书卡片一度直接从 Excel 工作簿取数。
- 这虽然能快速验证消息推送是否可用，但不符合长期结构设计。

## 决策内容

当前对 `market` 的结构约定进一步明确为三层：

1. 原始数据层
2. 指标计算层
3. 输出视图层
   - Excel 视图
   - 飞书卡片视图

同时明确：

1. 飞书卡片视图不应从 Excel 视图层反向取数。
2. Excel 视图和飞书卡片视图都应建立在同一套原始数据和指标计算结果之上。
3. 如果某个推送场景需要专门的聚合快照，应放在 `market/services/` 中构造，而不是让推送视图自己直接拼原始接口。

## 为什么这样定

1. Excel 是历史复盘输出，不应变成其他视图的唯一数据源。
2. 如果飞书卡片依赖 Excel，后续竞价卡片和盘中卡片会很难扩展，因为很多数据本来就不会先进 Excel。
3. 同一套原始数据和指标结果分别生成 Excel 视图、飞书卡片视图，更符合长期维护逻辑。
4. 这样可以避免“为了发消息而先造一份 Excel”这种反向依赖。

## 当前落实情况

1. 已新增：
   - `market/services/post_close_snapshot.py`
   - `market/push_views/post_close_card.py`
   - `market/jobs/push_post_close_card.py`
2. 第一版盘后卡片已改为直接走原始数据层和指标计算层。
3. 字段设计文档已补充三层结构和输出视图层约定。

## 后续待确认

2. 是否需要把“卡片快照”进一步做成统一的数据结构协议。

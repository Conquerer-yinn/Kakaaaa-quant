# 当前阶段 FastAPI 最小封装原则

## 结论

当前阶段允许引入 FastAPI，但只做最小封装层，不做完整任务平台。

## 当前已落地接口

1. `GET /health`
2. `GET /tasks`
3. `POST /tasks/daily-basics/run`
4. `POST /tasks/market-sentiment/run`

## 当前服务层目标

1. 把已有命令行任务补充为 HTTP 可调用入口。
2. 统一任务元数据和返回口径。
3. 保持 Excel 为主输出。
4. 为后续通知层和前端预留稳定入口。

## 当前明确不做

1. 不做数据库持久化。
2. 不做任务队列。
3. 不做复杂 `task_id` 生命周期管理。
4. 不做完整调度平台。
5. 不为了 API 反向重构现有研究工作流。

## 当前统一返回信息

当前运行接口至少返回：

1. `task_name`
2. `task_type`
3. `description`
4. `params`
5. `success`
6. `output_target`
7. `output_path`
8. `error_message`

# 子代理协作规则

## 背景

项目后续将长期依赖多个子代理并行推进旧脚本迁移、指标开发和策略开发。

## 决策内容

1. 主对话窗口负责：
   - 项目整体设计
   - 目录结构
   - 大模块计划
   - git / GitHub
   - 部署与整体协调
2. 子代理负责：
   - 旧脚本迁移
   - 新指标开发
   - 新策略开发
   - 某个具体任务的代码实现与调整
3. 子代理默认代码要求：
   - 代码尽量简洁、直接、可读
   - 关键逻辑要有必要的中文短注释，方便 review
   - 不为了抽象而抽象
   - 优先考虑维护成本
4. 子代理适合做事，但不应作为唯一长期知识库。

## 为什么这样定

1. 主窗口适合保留长期上下文。
2. 子代理适合并行推进具体事务。
3. 两者分工明确后，项目推进效率更高。

## 当前已建立的子代理方向

1. 指标设计迁移
2. 策略灵感系统化

## 分支策略

1. `main` 分支保持当前可用状态。
2. 文档、小修、小范围注释修改，可以直接在 `main` 上完成。
3. 旧脚本迁移、新指标开发、新策略开发、目录级调整，建议开独立分支。
4. 如果后续多个子代理并行开发，尽量一个子代理对应一个任务分支。
5. 分支完成后再合并回 `main`，避免长期在主分支上堆积未完成改动。

## 2026-03-28 对话摘要

### 主题一：市场情绪工作簿的形态

今天确认，市场情绪工作簿不再把重点放在“代码自动画出一套完美图表”，而是转向更贴合用户工作流的方案：

1. 代码长期负责维护原始数据 sheet。
2. 用户在 Excel 里手工建立图表模板。
3. 后续更新数据时，尽量让图表自动扩展到新数据，不再每次手工改图表索引。
4. 工作簿保留 `总览` 页，方便用户把图放在下面。

### 主题二：总览页需要恢复

今天用户明确提出：

1. `总览` 页是需要保留的。
2. 计划在总览页下方继续手工画图。
3. 因此总览页不能被取消。
4. 代码后续只应重写总览页上方摘要区，不应该覆盖下面的图表区域。

### 主题三：Excel Table 的利弊

今天确认：

1. 目前数据区带筛选按钮、蓝白条纹，是因为代码使用了 Excel Table。
2. 这样做的优点是图表更容易自动扩展数据源。
3. 缺点是外观不像用户以前那种纯原始数据表。
4. 后续可以继续保留 Table 机制，但样式上尽量收淡，减少“过于花”的感觉。

### 主题四：Tushare 请求频率

今天确认：

1. `run_market_sentiment.py` 目前通过环境变量 `TUSHARE_REQUEST_DELAY` 控制请求延迟。
2. 这不是命令行参数，所以 README 必须明确说明。
3. 常用方式：

```powershell
$env:TUSHARE_REQUEST_DELAY='0.5'
python market/jobs/run_market_sentiment.py --start-date 20260101 --end-date 20260326
```

4. 如果限流明显，可调到 `1` 或更高。

### 主题五：中文乱码问题

今天多次暴露出一个项目级问题：

1. 有些中文注释、README、配置常量、sheet 名、字段名会在写文件过程中被污染成 `?`。
2. 这不只是显示问题，还会直接导致代码运行错误，例如：
   - sheet 名非法
   - 列名匹配失败
   - 总览页变成问号
3. 这个问题已经确认需要作为项目级约束处理，不能再当成个别文件问题。
4. 相关规则已沉淀到：
   - `project_memory/decisions/2026-03-27_unicode_corruption_rules.md`

### 主题六：今天形成的执行共识

今天最终形成的长期共识是：

1. 市场情绪工作簿继续保留四个核心 sheet：`总览`、`总市场数据`、`高度观察`、`创业板专区`。
2. 图表优先由用户在 Excel 中建立模板。
3. 代码重点放在：
   - 数据正确性
   - 工作簿续写能力
   - 总览页摘要维护
   - 图表自动扩展所需的数据结构稳定性
4. 短期内优先继续核实：`最高连板`、`炸板数`、`十日高度个股`。

## 2026-04-01 对话摘要

### 主题一：市场字段设计文档独立落地

今天确认：

1. 市场字段设计文档需要独立放在 `market/` 目录下。
2. 该文档不能只写概念，必须同时区分：
   - 已实现字段
   - 规划字段
3. 已实现字段要能对应到真实代码锚点和真实 Excel 列名。
4. 规划字段允许先定义，但必须明确标注“待实现”。

### 主题二：`market` 三层结构进一步明确

今天进一步确认，`market` 后续按三层结构推进：

1. 原始数据层
2. 指标计算层
3. 输出视图层
   - Excel 视图
   - 飞书卡片视图

同时明确：

1. Excel 视图和飞书卡片视图是并列关系。
2. 飞书卡片不应从 Excel 文件反向取数。
3. 正确方式是基于同一套原始数据和指标计算结果，分别生成两种输出视图。

### 主题三：盘后飞书卡片第一版已真实跑通

今天已经补齐第一条真实消息推送链路：

1. `common/notifier/feishu_notifier.py`
2. `market/services/post_close_snapshot.py`
3. `market/push_views/post_close_card.py`
4. `market/jobs/push_post_close_card.py`

并且已经成功向测试飞书机器人发送过盘后复盘卡片。

### 主题四：盘后卡片抓数逻辑被精简

今天用户指出：盘后卡片的字段不应需要近 45 天整段数据，这个判断是对的。

问题原因是：

1. 第一版卡片实现时，错误复用了 `market_sentiment` 的综合研究式抓数逻辑。
2. 导致盘后卡片一度按近 45 天整段交易日循环抓取多张日表。

随后已经调整为“按字段反推最小抓数集”：

1. 十日高度只抓最近 11 个交易日 `daily`
2. 次日反馈只抓最近 2 个交易日：
   - `daily`
   - `daily_basic`
   - `limit_list_d`
   - `stk_limit`
3. `stock_basic` 只抓 1 次

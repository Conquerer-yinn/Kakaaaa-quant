# 代码编写规范

这份文件用于统一项目中的代码风格要求，主对话和子代理都应遵守。

## 核心要求

1. 代码尽量简洁、直接、可读。
2. 关键逻辑必须有必要的中文短注释，方便 review。
3. 不为了抽象而抽象。
4. 优先考虑维护成本和后续可读性。
5. 命名要清晰，让人一眼知道变量、函数、脚本在做什么。

## 注释原则

1. 注释重点解释“为什么这样写”和“这段逻辑在做什么”。
2. 不写无意义的逐行注释。
3. 复杂流程、口径转换、兼容性处理、重要约定，需要注释说明。
4. 注释默认使用中文。

## 结构原则

1. 小任务先求清楚，再求抽象。
2. 只有当逻辑会复用、会反复修改、会被多处调用时，再考虑抽离。
3. 一次性任务不要过度工程化。

## review 视角

写代码时默认假设：

1. 后面需要由人快速 review。
2. 后面可能换别的 AI 接手。
3. 后面几周后自己再回来读，也要容易看懂。
